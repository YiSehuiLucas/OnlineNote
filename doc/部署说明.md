# OnlineNote 部署说明

本文档介绍将 OnlineNote 部署到一台 Linux 服务器（以 Ubuntu/Debian 为例）的完整流程：本地交叉编译 → 上传 → systemd 守护 → nginx 对外 → 验证与升级。

> 文中 `<服务器IP>`、`<用户名>`、`<密码>`、`<你的域名>` 均为占位符，请替换为你的真实值。

## 1. 部署架构

```
浏览器 ──HTTP──▶ nginx(:80) ──/api/──▶ Go 服务(127.0.0.1:8080)
                    │
                    └── /（静态资源）── /opt/onlinenote/web/
```

- Go 服务只监听 `127.0.0.1:8080`，不对公网开放；
- 前端是零构建静态页面，由 nginx 直接托管；
- 数据全部落在 `/opt/onlinenote/data/`（SQLite + 笔记文件树）。

## 2. 编译 Linux 二进制（任意操作系统上执行）

SQLite 使用纯 Go 驱动，**免 CGO**，可直接交叉编译：

```bash
# 在项目根目录执行。首次为 Linux 目标补齐依赖：
GOOS=linux GOARCH=amd64 go mod tidy

# 编译
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags '-s -w' -o bin/note-linux-amd64 ./cmd/note
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags '-s -w' -o bin/notectl-linux-amd64 ./cmd/notectl
```

## 3. 上传到服务器

```bash
# 创建目录
ssh <用户名>@<服务器IP> 'mkdir -p /opt/onlinenote/{bin,configs,web}'

# 上传二进制与前端
scp bin/note-linux-amd64   <用户名>@<服务器IP>:/opt/onlinenote/bin/note
scp bin/notectl-linux-amd64 <用户名>@<服务器IP>:/opt/onlinenote/bin/notectl
scp -r web/*               <用户名>@<服务器IP>:/opt/onlinenote/web/
scp configs/config.yaml    <用户名>@<服务器IP>:/opt/onlinenote/configs/config.yaml
```

> Windows 也可用 `pscp`/WinSCP 等工具完成同样操作。

## 4. 服务器端配置

### 4.1 修改 config.yaml

```bash
ssh <用户名>@<服务器IP> 'chmod +x /opt/onlinenote/bin/*'
ssh <用户名>@<服务器IP> 'vi /opt/onlinenote/configs/config.yaml'
```

必改项：

| 配置项 | 说明 |
|--------|------|
| `server.addr` | 保持 `127.0.0.1:8080`（仅本机，由 nginx 对外）；若本机 8080 已被其他服务占用，可改为 `127.0.0.1:8081` 等，同时同步修改 nginx 的 `proxy_pass` |
| `auth.session_secret` | **务必改成随机值**，例如 `openssl rand -hex 32` 的输出 |
| `auth.max_users` | 注册人数上限，按需调整 |

### 4.2 初始化数据库

```bash
# 注意：必须在 /opt/onlinenote 目录下执行（配置里的路径是相对路径）
ssh <用户名>@<服务器IP> 'cd /opt/onlinenote && ./bin/notectl -config configs/config.yaml db init'

#（可选）预置账号
ssh <用户名>@<服务器IP> 'cd /opt/onlinenote && ./bin/notectl -config configs/config.yaml user add -username <账号> -password <密码>'
```

## 5. systemd 守护

```bash
# 把仓库 deploy/onlinenote.service 上传后安装
scp deploy/onlinenote.service <用户名>@<服务器IP>:/tmp/onlinenote.service
ssh <用户名>@<服务器IP> 'install -m 644 /tmp/onlinenote.service /etc/systemd/system/onlinenote.service'

# 启动并设置开机自启
ssh <用户名>@<服务器IP> 'systemctl daemon-reload && systemctl enable --now onlinenote'
ssh <用户名>@<服务器IP> 'systemctl status onlinenote'   # 应显示 active (running)
```

## 6. nginx 对外

### 6.1 有域名时（推荐）

```bash
scp deploy/nginx.conf <用户名>@<服务器IP>:/tmp/onlinenote.conf
ssh <用户名>@<服务器IP> 'sed -i "s/note.example.com/<你的域名>/" /tmp/onlinenote.conf'
ssh <用户名>@<服务器IP> 'install -m 644 /tmp/onlinenote.conf /etc/nginx/conf.d/onlinenote.conf'
ssh <用户名>@<服务器IP> 'nginx -t && nginx -s reload'
```

### 6.2 仅用 IP 访问、且 80 端口已与其他站点共存时

当服务器 80 端口已有站点（例如存在 `default_server`）时，可以按 **Host 头分流**：把下面的配置写入 `/etc/nginx/conf.d/onlinenote.conf`，`server_name` 填服务器 IP。这样「以 IP 访问」的请求进入 OnlineNote，其他域名的请求仍走原有站点：

```nginx
server {
    listen 80;
    server_name <服务器IP>;

    root /opt/onlinenote/web;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;   # 与 config.yaml 的端口一致
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 10m;
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/markdown;
}
```

> 注意：此方式会让「直接以 IP 访问 80 端口」的流量指向 OnlineNote；若原有站点也依赖 IP 访问，请改用域名分流（6.1）或将 OnlineNote 放到独立端口。

## 7. 防火墙 / 云安全组

- 只需放行 **80**（以及 SSH 22）。8080 等服务端口只监听本机，无需对外开放；
- 若你想让 Go 直接对外（不走 nginx），需在云控制台安全组中放行对应端口，并把 `server.addr` 改为 `0.0.0.0:<端口>`（不推荐，失去 nginx 的静态托管与统一入口）。

## 8. 验证

```bash
# 服务器本机
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/          # 200
curl -s http://127.0.0.1:8080/api/auth/me                                  # {"error":"未登录或会话已过期"}

# 外部
curl -s -o /dev/null -w "%{http_code}\n" http://<你的域名或服务器IP>/     # 200
```

浏览器打开后注册账号（或使用预置账号）即可使用。

## 9. 升级

```bash
# 重新编译后重复第 3 步上传，然后：
ssh <用户名>@<服务器IP> 'systemctl restart onlinenote && systemctl status onlinenote --no-pager'
```

- 静态资源（`web/`）更新后按 Ctrl+F5 强刷浏览器即可；
- 升级不会影响 `data/` 下的笔记与数据库。

## 10. 备份与恢复

```bash
# 备份（data 目录包含 note.db 与全部笔记文件）
ssh <用户名>@<服务器IP> 'tar -czf /root/onlinenote-backup-$(date +%Y%m%d).tar.gz -C /opt/onlinenote data'

# 恢复：停止服务 → 解包回 /opt/onlinenote/ → 启动
```

## 11. 常见问题

1. **`notectl user list` 看不到账号**：`database.path` 是相对路径，必须在 `/opt/onlinenote` 目录下执行 `notectl`，否则会在别的目录生成/读取另一个数据库文件。
2. **`systemctl reload nginx` 报 not active**：服务器上的 nginx 可能不是以 systemd 方式运行的，改用 `nginx -s reload`。
3. **外部访问 502/超时**：先确认 Go 服务本机是否正常（第 8 节），再检查云安全组是否放行了 80；`502` 通常表示 nginx 能通但后端没起来（`systemctl status onlinenote`）。
4. **8080 端口被占用**：`ss -tlnp | grep 8080` 查看占用方；把 `config.yaml` 的端口与 nginx 的 `proxy_pass` 一起改成新端口（如 8081）即可。
5. **忘记密码 / 误删账号**：`notectl user add` 重新预置账号，或直接编辑注册上限后重新注册。
