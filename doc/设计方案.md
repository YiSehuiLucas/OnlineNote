# OnlineNote 在线笔记软件 —— 初版技术方案（v1.1）

> **变更说明**：相对 v1.0 方案，本次新增**用户注册**功能（注册人数上限默认 5 人，可通过配置调整），前端实现方式调整为**零构建静态前端**。其余设计保持不变。

## 1. 项目概述

个人自用的在线笔记软件：通过浏览器访问，笔记以 Markdown 文件的形式按目录树组织，登录后即可查看、编辑、管理笔记。后端主体用 Go 实现，nginx 作为唯一对外入口。

**初版目标**：能用、够用、结构清晰，为后续扩展留好接口。

---

## 2. 需求拆解与对应方案

| # | 需求 | 方案 |
|---|------|------|
| 1 | 浏览器打开 | B/S 架构：前端静态页面 + 后端 REST API |
| 2 | 支持 MD 语法 | 笔记以 `.md` 文件存储；编辑器语法编辑 + 右侧实时渲染预览 |
| 3 | 目录树文件显示 | 服务端文件系统即数据源：`data/notes/` 下的真实目录/文件直接映射为浏览器中的目录树，支持折叠、新建、重命名、删除 |
| 4 | 登录 + 注册（限制人数） | SQLite 建 `users` 表；**支持注册，注册人数上限默认 5（`auth.max_users` 可配置），满员后注册接口返回 403**；密码 bcrypt 哈希入库；HMAC Cookie 会话认证 |
| 5 | nginx 反向代理 | nginx 对外监听 80/443：静态资源直接由 nginx 提供，`/api/` 反向代理到 Go 服务 |
| 6 | Go 主体 | 后端全部逻辑用 Go 实现（路由、认证、文件读写、会话管理、注册限额） |

**初版明确不做**：找回密码、多级权限、附件上传、全文搜索、版本历史、HTTPS、Docker 化。

---

## 3. 与首版方案的差异

1. **新增注册**：原方案"仅预置账号、不做注册"，现改为开放注册，但通过 `auth.max_users`（默认 5）限制账号总数。预置管理员账号（`notectl user add`）同样计入名额。
2. **前端零构建**：原方案前端为 Vue3 + Vite + Element Plus，现初版改为原生 HTML/CSS/JS 静态页面（含自研轻量 Markdown 渲染器）。理由：
   - 初版功能简单（登录/注册 + 目录树 + 编辑/预览），无需引入完整前端构建链；
   - nginx 可直接托管，部署少一步构建，依赖完全可控；
   - 后续界面复杂化时可平滑迁移到 Vue3 + Vite（API 层保持不变）。
3. **会话实现**：由 `gin-contrib/sessions` 改为**自实现 HMAC 签名 Cookie 会话**（约 60 行代码）：签名校验 + 过期控制 + HttpOnly/SameSite，实现简单可控、少两个外部依赖。

## 4. 技术选型

### 4.1 后端

| 项 | 选型 | 理由 |
|----|------|------|
| 语言 | Go 1.22+ | 需求指定；单二进制部署简单 |
| Web 框架 | Gin | 路由与中间件生态成熟，开发效率高 |
| 数据库 | SQLite（纯 Go 驱动 `modernc.org/sqlite`） | 少量用户场景足够，免 CGO、单文件、易备份 |
| 密码哈希 | `golang.org/x/crypto/bcrypt` | 即使直接写库也绝不存明文 |
| 会话 | 自实现 HMAC Cookie 会话 | 签名校验 + 过期控制，无额外依赖 |
| 配置 | YAML（`gopkg.in/yaml.v3`） | 一份配置文件管所有参数 |

### 4.2 前端（零构建静态页面）

- 原生 HTML/CSS/JS，三个文件：`index.html` / `style.css` / `app.js` + `md.js`（轻量 Markdown 渲染器）。
- 渲染器支持：标题、分隔线、引用、无序/有序列表、代码块与行内代码、链接、图片、粗体/斜体/删除线、段落换行；渲染前统一 HTML 转义防注入。
- 编辑交互：`Ctrl+S` 保存、实时防抖预览、目录树右键菜单（新建/重命名/删除）。

## 5. 总体架构

```
                       浏览器
                         │  http://note.example.com
                         ▼
              ┌─────────────────────┐
              │  nginx  (80/443)     │
              │  ├─ /      静态资源   │  web/（无需构建）
              │  └─ /api/  反向代理 ──┼──────────┐
              └─────────────────────┘          │
                                               ▼
                        ┌──────────────────────────────┐
                        │  Go 服务 (Gin, 127.0.0.1:8080) │
                        │  ├─ 会话认证中间件             │
                        │  ├─ /api/auth  注册/登录/登出   │
                        │  └─ /api/file  目录树/读写/增删 │
                        └───────┬──────────────┬─────────┘
                                │              │
                        ┌───────▼──────┐  ┌────▼─────────────┐
                        │ data/note.db │  │ data/notes/       │
                        │ users 表     │  │ 真实目录树(.md)   │
                        └──────────────┘  └──────────────────┘
```

要点：
- Go 只监听 `127.0.0.1:8080`，**不对公网开放**，统一由 nginx 入口管理（本地开发时也可由 Go 直接托管 `web/` 静态文件）。
- 笔记就是磁盘上的真实文件：备份、迁移、离线查看都直观。

## 7. 数据设计

### 7.1 数据库（仅一张表）

```sql
CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,          -- bcrypt 哈希，绝不存明文
    created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 7.2 注册人数上限

- 上限由配置项 `auth.max_users` 控制，**默认 5**。
- 注册接口在插入前先 `COUNT(*)` 比对上限：满员返回 `403`（错误信息中带当前上限值）。
- 预置账号（`notectl user add`）与注册账号共用同一张表，**都计入名额**。
- 注册成功后自动登录（下发会话 Cookie）。

### 7.3 笔记存储

- 笔记**不入库**，直接落盘为 `data/notes/**/*.md`，目录树即文件系统目录树。
- 只管理 `.md` 文件与目录，其他类型文件与隐藏文件（`.` 开头）在树中隐藏。
- 同一时刻少量用户使用，文件读写用"读全部→改→整体写回"的最简模型。

## 8. 接口设计（REST API）

> 除注册/登录外，所有接口要求登录态；`path` 均为相对笔记根目录的相对路径，统一做路径穿越校验。

### 8.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | `{username, password}` 注册，成功自动登录；满员 403、重名 409 |
| POST | `/api/auth/login` | `{username, password}` 登录，成功 Set-Cookie 会话 |
| POST | `/api/auth/logout` | 销毁会话 |
| GET  | `/api/auth/me` | 返回当前登录用户（前端用于路由守卫） |

注册校验规则：用户名 `2-32` 位字母/数字/`_`/`-`；密码 `6-72` 位。

### 8.2 文件树与文件

| 方法 | 路径 | 说明 |
|------|------|------|
| GET    | `/api/tree` | 返回整棵目录树（`name / path / type: dir|file / children`） |
| GET    | `/api/file?path=a/b.md` | 读取文件内容 |
| PUT    | `/api/file` | `{path, content}` 保存文件（自动补 `.md` 后缀） |
| POST   | `/api/file` | `{path}` 新建文件 |
| DELETE | `/api/file?path=a/b.md` | 删除文件 |
| POST   | `/api/dir` | `{path}` 新建目录 |
| DELETE | `/api/dir?path=a/b` | 删除目录（仅空目录可删，防误删） |
| PUT    | `/api/move` | `{from, to}` 重命名/移动（文件与目录通用） |

## 9. 前端页面设计

- **登录/注册页**：同一卡片切换；注册表单校验两次密码一致；显示注册人数受限提示。
- **主界面**（三栏布局）：
  - **左侧**：目录树，支持折叠/展开、右键菜单（新建笔记/文件夹、重命名、删除），顶部工具栏"新建笔记/新建文件夹/刷新"。
  - **中间**：Markdown 编辑器（textarea，等宽字体，`Ctrl+S` 保存，顶部显示保存状态）。
  - **右侧**：实时渲染预览（防抖 300ms）。
- **行为**：页面加载先调 `/api/auth/me`，未登录显示登录页；接口返回 401 时同样切回登录页。

---

## 10. 安全设计

1. **密码**：bcrypt 哈希入库，代码中不存在明文。
2. **会话**：Cookie 值 = Base64(载荷) + HMAC-SHA256 签名，服务端校验签名与过期时间；Cookie 设 `HttpOnly` + `SameSite=Lax`。
3. **路径穿越防护**：所有文件操作先规范化（统一 `/`、`Clean`），拒绝绝对路径、`..`、反斜杠等，并校验结果仍在笔记根目录内。
4. **注册限额**：`COUNT` + 上限判断在插入前完成；用户名唯一约束兜底防并发重名。
5. **登录/注册防爆破**：按 IP 简单计数限速（10 次 / 5 分钟，返回 429）。
6. **XSS**：Markdown 渲染前统一 HTML 转义；链接/图片仅允许 http(s)、相对路径等安全协议。
7. **信息泄露**：文件不存在的错误不透露真实绝对路径。

## 11. nginx 配置示例（deploy/nginx.conf）

```nginx
server {
    listen 80;
    server_name note.example.com;

    # 前端静态资源（零构建，直接托管 web/）
    root /opt/onlinenote/web;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    # API 反向代理到 Go 服务
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 10m;          # 大笔记保存上限
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/markdown;
}
```

## 12. 应用配置示例（configs/config.yaml）

```yaml
server:
  addr: "127.0.0.1:8080"        # 仅本机监听，由 nginx 对外
  static: "./web"               # 前端静态目录（开发模式由 Go 直接托管）
auth:
  max_users: 5                  # 注册人数上限（含预置账号）
  session_secret: "change-me"   # 会话签名密钥，部署时务必修改
  session_max_age_hours: 168
storage:
  root: "./data/notes"          # 笔记根目录
database:
  path: "./data/note.db"
```

## 15. 假设与约束

1. **多用户但小规模**：注册开放，账号总数默认上限 5（可配置），无找回密码流程。
2. **笔记格式**：只管理 `.md` 文本文件，不支持附件。
3. **部署环境**：按 Linux 服务器写部署文档；代码本身跨平台，Windows 本机开发调试同样支持。
4. **编辑模式**：分屏实时预览；如需所见即所得可在 v2 引入成熟编辑器组件。
5. 若未来有公网异地访问需求，v2 需增加 HTTPS——本期先按内网或纯 HTTP 规划。
